# وثائقي

مساحة عمل عربية لإدارة الوثائق الرسمية، مخصصة حالياً لحساب المالك. يتضمن هذا الفرع نسخة الويب وخدمة API المبنية على Appwrite.

> **حالة هذا الفرع:** ترحيل تقني قيد التحقق. لا تعتبر هذه النسخة منشورة للإنتاج، ولا تدمج إلى `main` قبل اكتمال قائمة التحقق في `docs/migrations/APPWRITE_MIGRATION_PLAN_AR.md`.

## نطاق الإصدار الحالي

الوظائف النشطة في واجهة المالك:

- تسجيل الدخول وإدارة جلسة المالك باستخدام Appwrite Auth.
- إعداد كلمة مرور حساب المالك الحالي عبر مسار إعداد لمرة واحدة.
- مساحة الوثائق: إنشاء الوثائق وتعديل المسودات وإصدارها وأرشفتها.
- قوالب الوثائق وحقولها وإصداراتها.
- إعدادات ترويسة الوثيقة وترقيمها حسب المؤسسة.
- الملف الشخصي وإعدادات الوثائق العامة.
- سجل تدقيق لعمليات المالك.

**الميزات القديمة غير المتاحة في هذا النطاق:** إرسال واستقبال البرقيات، مسارات الإحالة والموافقات، الإدارة التشغيلية متعددة المؤسسات، الإشعارات التشغيلية القديمة، وشاشات الإدارة القديمة. وجود أنواع أو مكونات عرض مشتركة في الشيفرة لا يعني أن هذه الوظائف متصلة أو مدعومة في هذا الإصدار. لا تُعدّل هذه الوظائف أو تُعد إلى الواجهة دون طلب مستقل وتنفيذ واختبارات مكافئة.

## البنية التقنية

- **الواجهة:** React وTypeScript وVite وTailwind CSS، مع دعم RTL.
- **API:** tRPC مستضاف في Appwrite Function باسم `wathaeqi-api`.
- **المصادقة:** Appwrite Auth، مع جلسة HttpOnly موقعة من الخادم.
- **قاعدة البيانات:** Appwrite TablesDB ضمن قاعدة `wathaeqi-db`.
- **الملفات:** Appwrite Storage عبر موفر التخزين الخادمي.
- **الاستضافة التجريبية:** Appwrite Site مستقل باسم `wathaeqi-preview` مرتبط بفرع الترحيل.
- **بيئة الإنتاج:** منفصلة عن هذا الفرع؛ لا تغيّر إعداداتها أو تنشر إليها ضمن أعمال الترحيل.

لا يعتمد مسار تشغيل المالك والوثائق الحالي على Supabase أو PostgreSQL أو Drizzle. إزالة ملفات الترحيل القديمة من المستودع لا تحذف أي مشروع أو بيانات خارجية في Supabase.

## إعداد البيئة المحلية

المتطلبات:

- Node.js 24 أو أحدث.
- pnpm 12.14.0.
- مشروع Appwrite مع Auth وTablesDB وStorage وFunction مهيأة وفق مستندات الترحيل.

ابدأ من جذر المستودع:

```bash
corepack enable
pnpm install --frozen-lockfile
cp .env.example .env
```

اضبط المتغيرات التالية في بيئة الخادم المحلية فقط:

| المتغير | الغرض |
| --- | --- |
| `APPWRITE_ENDPOINT` | عنوان Appwrite وينتهي بـ `/v1` |
| `APPWRITE_PROJECT_ID` | معرّف مشروع Appwrite |
| `APPWRITE_DATABASE_ID` | معرّف قاعدة TablesDB |
| `APPWRITE_BUCKET_ID` | معرّف حاوية الملفات عند استخدام التخزين |
| `APPWRITE_API_KEY` | مفتاح خادمي بصلاحيات محدودة؛ لا يُرسل إلى المتصفح |
| `AUTH_SESSION_SECRET` | سر توقيع الجلسات، 32 محرفاً عشوائياً على الأقل |
| `OWNER_SETUP_SECRET` | رمز إعداد المالك لمرة واحدة، 32 محرفاً على الأقل |
| `APPWRITE_SESSION_COOKIE_SAMESITE` | استخدم `None` عند فصل نطاق الواجهة عن نطاق الوظيفة عبر HTTPS |

يحتاج عميل الواجهة إلى:

- `VITE_APPWRITE_API_URL`: عنوان Function العام، وليس سراً.
- `VITE_APPWRITE_PROJECT_ID` و`VITE_APPWRITE_ENDPOINT` فقط إذا كانت واجهة العميل تستخدمهما مباشرة.

لا تضع مفاتيح API أو أسرار الجلسة أو رمز إعداد المالك في متغير يبدأ بـ `VITE_`. لا ترفع ملف `.env` إلى Git.

في Appwrite Function تُستخدم هوية التنفيذ ومفتاحها قصير العمر عند توفرهما؛ لا تنسخ مفتاحاً خادمياً إلى ملفات الواجهة. يجب أن تحتوي `APPWRITE_WEB_ORIGINS` على أصول الويب المسموح بها حرفياً، مفصولة بفواصل.

## تشغيل وبناء المشروع

```bash
pnpm dev
```

فحوص الجودة:

```bash
pnpm lint
pnpm check
pnpm check:responsive-shell
pnpm test
pnpm build:appwrite-api
pnpm build
```

بناء حزمة Appwrite API يتحقق أيضاً من عدم تضمين استيراد SDK الخاص بـSupabase. لا تعتبر نجاح البناء وحده إثباتاً لعمل تسجيل الدخول أو الجلسات أو عمليات الوثائق على الخدمة الحية.

## اختبار Appwrite

يجب اختبار هذه المسارات على بيئة معاينة معزولة، وليس عبر الكتابة التجريبية في بيانات الإنتاج:

1. فتح الواجهة من نطاق المعاينة المصرح به في Appwrite.
2. التأكد من نجاح طلب `auth.ownerSetupStatus` وظهور حالة الإعداد قبل إدخال رمز المالك.
3. اختبار تسجيل الدخول بحساب المالك الحالي، دون إنشاء حساب بديل.
4. اختبار إنشاء قالب وتعديله وتعطيله، والتحقق من حفظه.
5. اختبار إنشاء وثيقة كمسودة وتعديلها وإصدارها وأرشفتها.
6. اختبار عزل الملكية ومنع قراءة وثائق أو قوالب مالك آخر.
7. اختبار تعارض التحديث والترقيم المتزامن، والتأكد من عدم تكرار الأرقام.
8. اختبار تسجيل الخروج وانتهاء الجلسة وتغيير كلمة المرور.
9. اختبار الرفع والتنزيل فقط إذا كانت ميزة الملفات مفعلة في واجهة الإصدار.

معاينات Appwrite الخاصة قد تتطلب تسجيل الدخول إلى حساب عضو في المؤسسة المالكة للمشروع والتصريح لتطبيق **Appwrite Preview**. فشل فتح رابط المعاينة بسبب بوابة تسجيل الدخول لا يثبت فشل API ولا يثبت نجاح الواجهة.

## قواعد البيانات والبيانات

تستخدم مستودعات التطبيق الحالية جداول Appwrite مثل `users` و`organizations` و`organization_memberships` و`documents` و`templates` و`department_settings` و`platform_document_settings` و`app_records`، إضافة إلى جداول التدقيق عند تفعيلها. راجع `docs/migrations/APPWRITE_SCHEMA_COMPATIBILITY_AUDIT_AR.md` لمراجعة التوافق والحدود.

- لا تنقل بيانات تشغيل تاريخية ضمن هذا الترحيل.
- لا تحذف أو تعدّل بيانات مشروع Supabase الخارجي.
- لا تحذف سجلات أو ملفات Appwrite الموجودة.
- احتفظ بحساب المالك الحالي ومعرّف Appwrite Auth المرتبط به.
- لا تستخدم قاعدة الإنتاج للاختبارات أو لإنشاء بيانات اختبار.
