# منصة وثائقي

منصة عربية آمنة لإدارة الوثائق والعمليات الشرطية بواجهة ويب متجاوبة وخادم API مركزي. تطبيق Flutter عميل مستقل على الفرع `flutter-mobile-app` ويتصل بالخادم نفسه. تشمل المنصة دورة حياة الوثائق، الجهات والصلاحيات، المرفقات، سجل التدقيق، التقارير، الاستيراد والتصدير، والإشعارات.

## البنية التقنية

- **الواجهة:** React وTypeScript وVite وTailwind CSS، مع دعم RTL والوضعين الفاتح والداكن.
- **الخادم:** Express وtRPC، ويُقدَّم عبر Netlify Functions مع مسار صحة مستقل `/api/health`.
- **المصادقة:** Appwrite Auth مع جلسات موقعة على الخادم.
- **قاعدة البيانات والتخزين:** Appwrite مستخدم للمصادقة والملفات ومرفقات البرقيات وشعارات الجهات وسجلات التدقيق وبعض إعدادات المنصة والجهات. نقل بقية بيانات الأعمال ما زال جارياً؛ لا تزال عمليات البرقيات ومساراتها وسجلات اشتراكات الإشعارات الفورية والحذف النهائي للحسابات تعتمد على Supabase.
- **تطبيق الهاتف:** Flutter على فرع التطوير المستقل `flutter-mobile-app`، مع تخزين جلسة آمن ومزامنة العمل دون اتصال وإشعارات Firebase.
- **النشر:** Netlify للواجهة وواجهات API.

## المتطلبات

- Node.js 24 أو أحدث؛ الإصدار مثبت أيضًا في ملف `.nvmrc`.
- pnpm 12.14.0، ويمكن تفعيله عبر Corepack.
- مشروع Appwrite وإعدادات الخادم اللازمة للمصادقة وقاعدة البيانات والتخزين.
- Docker وSupabase CLI لتشغيل اختبارات قاعدة البيانات القديمة فقط إلى أن يكتمل نقل جميع المسارات إلى Appwrite.
- Flutter 3.47.2 للعمل على تطبيق الهاتف بعد الانتقال إلى فرعه المستقل.

## بدء العمل على الويب والخادم

```bash
corepack enable
pnpm install --frozen-lockfile
cp .env.example .env
```

املأ إعدادات Appwrite المطلوبة في `.env`. يحتاج تسجيل الدخول إلى `AUTH_SESSION_SECRET` عشوائي لا يقل عن 32 محرفًا. لا ترفع ملف البيئة أو أي أسرار إلى Git، ولا تضع مفاتيح الخادم في متغيرات تبدأ بـ`VITE_`.

**تنبيه أثناء الترحيل:** مسار API يعمل على Netlify، وعمليات التخزين ومرفقات البرقيات وشعارات الجهات أصبحت على Appwrite. ما زالت عمليات بيانات البرقيات ومساراتها وسجلات اشتراكات الإشعارات الفورية والحذف النهائي للحسابات بحاجة إلى النقل والاختبار. كما أن تسجيل الدخول على الموقع المنشور يحتاج ضبط `AUTH_SESSION_SECRET` في Netlify قبل أن يصبح متاحًا.

ثم شغّل بيئة التطوير:

```bash
pnpm dev
```

لإنشاء نسخة الإنتاج وتشغيلها:

```bash
pnpm build
pnpm start
```

## فحوص الجودة

```bash
pnpm lint
pnpm check
pnpm check:responsive-shell
pnpm test
pnpm build
```

يتحقق اختبار المعاينة في GitHub Actions من مساري `/api/health` و`/api/trpc/auth.me` على Netlify Deploy Preview. اختبارات قاعدة البيانات المحلية ما زالت تشغّل ترحيلات واختبارات Supabase القديمة لأن بعض إجراءات الأعمال لم تُنقل بعد. لا تستخدم قاعدة الإنتاج للاختبار، ولا تعدّل ترحيلًا سبق تطبيقه لتغيير التاريخ المخفي للمخطط.

الويب والهاتف واجهتان للنظام نفسه، لكن مصدر الشيفرة منفصل: يحتوي `main` الويب والخادم، ويحتوي `flutter-mobile-app` عميل Flutter وفحوصه. يتصل الهاتف بـAPI الخادم نفسه؛ تظل المصادقة والصلاحيات ونطاق الجهة مسؤولية الخادم. يجب مراجعة تغييرات API والبيانات من الفرعين معًا، وفق `docs/WEB_MOBILE_INTEGRATION_AR.md`.

## تطبيق الهاتف

للحصول على نسخة التطبيق لأول مرة:

```bash
git fetch origin
git switch --track origin/flutter-mobile-app
cd mobile
```

بعدها شغّل فحوص Flutter من مجلد `mobile/`:

```bash
flutter pub get
dart format --output=none --set-exit-if-changed lib test
flutter analyze
flutter test
flutter build apk --debug
```

يستخدم التطبيق عنوان الخادم الافتراضي الموضح في `mobile/lib/api.dart`، ويمكن تغييره أثناء التطوير:

```bash
flutter run --dart-define=API_BASE_URL=http://10.0.2.2:3000
```

راجع `mobile/README.md` و`mobile/FIREBASE_SETUP_AR.md` لتفاصيل الهاتف والإشعارات.

## أهم المجلدات

| المسار | المحتوى |
| --- | --- |
| `client/src` | صفحات الويب والمكونات وأدوات العرض والتصدير |
| `client/src/features/telegrams/documents` | وحدات مستندات الوثائق واختباراتها المنقولة تدريجيًا |
| `server` | إجراءات tRPC والصلاحيات والتخزين والاختبارات |
| `netlify/functions` | وظائف Netlify الخاصة بواجهة API وفحص الصحة |
| `shared` | الأنواع والقواعد المشتركة بين الواجهة والخادم |
| `supabase` | ترحيلات واختبارات قاعدة البيانات القديمة المستخدمة أثناء إكمال النقل |
| `flutter-mobile-app:mobile` | تطبيق Flutter واختباراته على فرع مستقل |
| `docs` | التشغيل والأمان والصلاحيات والتصميم والنسخ الاحتياطي |

لخريطة ملكية المجلدات وقواعد نقل الوحدات بأمان، راجع [`docs/architecture/REPOSITORY_STRUCTURE_AR.md`](docs/architecture/REPOSITORY_STRUCTURE_AR.md).

## قواعد التعديل الآمن

- حافظ على جميع الميزات ومسارات الصلاحيات الحالية، وأضف اختبارات للتغييرات السلوكية.
- لا تعتمد إخفاء زر في الواجهة بديلًا عن التحقق من الصلاحية في الخادم.
- لا تسجل كلمات المرور أو الجلسات أو البيانات الحساسة، ولا تضع أسرار الخادم في متغيرات تبدأ بـ`VITE_`.
- استخدم فرعًا مستقلًا وطلب مراجعة، وانتظر نجاح GitHub Actions قبل الدمج.

لمزيد من الإرشادات راجع `CONTRIBUTING.md` و`SECURITY.md` و`docs/OPERATIONS_AR.md`.
