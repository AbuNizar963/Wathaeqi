# مساحة الوثائق — عقد الويب وFlutter

## النطاق وحدود الثقة

التغييرات تخص `Wathaeqi/main` للويب و`Wathaeqi/flutter-mobile-app` لـDart/Flutter. المرجع `police-telegrams-platform` يُقرأ فقط من أرشيفين محليين غير مرتبطين بـGit. لا تغيير في Appwrite Auth أو TablesDB أو Storage ولا كتابة اختبارية في بيانات الإنتاج.

المستخدم المسجل يطلب عرض أو تنزيل وثيقة يملك صلاحية الوصول إليها. المعرّف واسم الملف وعنوان URL مدخلات غير موثوقة؛ صلاحية الوصول تبقى قرار الخادم. لا يجوز استبدال مسار الملف المصادق عليه برابط عام، أو تضمين مفتاح Appwrite في العميل. فشل الطلب أو التحضير يجب أن ينهي المؤشر برسالة واضحة ويحرر الموارد المؤقتة، لا أن يُعامل كنجاح.

## هوية واحدة

خط الواجهة Cairo، مع إبقاء Aref Ruqaa داخل الوثائق الرسمية. اللون الأساسي `#0f766e`، الخلفية `#f4f7f8`، البطاقة `#ffffff`، النص `#172b36`، حدود السطح `#dbe5e8`، والشريط الجانبي `#102e3c`. يبقى الذهبي `#c9964d` تفصيلاً ثانوياً وتبقى ألوان الوضع الداكن الفاتحة القائمة. العلامة الحالية محفوظة لتجنب قطع التعرف على النظام.

العنوان «مساحة الوثائق»، والوصف «أنشئ، نظّم، واطبع. وثائقك وقوالبك وملفاتك في مكان واحد.» يستخدم الدخول عنوان «وثائقك. منظّمة وواضحة.» ومسميات إجراءات عربية موجزة. الأيقونات من عائلة Lucide أو النظير الأصلي في Flutter.

## القسم الموحد

المسار الأساسي للويب `/documents`. الروابط السابقة `/` و`/dashboard` و`/studio` تُوجَّه إليه مع الحفاظ على الاستعلام ومعرّف الوثيقة وأمر الإنشاء. التبويبات مرتبة: «الوثائق»، «القوالب»، «الأرشيف»، «الملفات». الملفات عرض مدمج داخل مساحة العمل، لا قسم مستقل في التنقل. تُحفظ وظائف محرر الوثائق والقوالب والحقول والإصدار والأرشفة، وإدارة الملفات والبحث المحفوظ والفرز والتصفية والطباعة الأصلية.

## الطباعة والتقدم

المقصود بالطباعة المباشرة فتح حوار النظام من التطبيق الحالي، لا الطباعة الصامتة إلى طابعة دون موافقة المستخدم. نمط المرجع يجهز DOM للورقة ثم يستدعي `window.print()`؛ Flutter يستخدم مسار الطباعة الأصلي. لا حاجة إلى نافذة متصفح مستقلة أو رابط خارجي.

النسبة أثناء التحضير تمثل مراحل تجهيز، ولا تعني تقدم الطابعة. حيث تتوفر بايتات إجمالية يُقاس تقدم النقل فعلياً؛ وعندما لا تتوفر نسبة حقيقية تُعرض رسالة المرحلة بصدق. اكتمال التحضير أو إرسال طلب الطباعة ليس إثباتاً لخروج الورقة. لا يمكن للمتصفح إثبات أن المستخدم حفظ التنزيل على القرص.

## التحقق والتسليم

تُشغّل أوامر الأنواع والتنسيق والاختبارات والبناء لكل فرع مستقلاً. لا دمج للفرعين ولا force-push. نتائج GitHub Actions تُراجع على SHA النهائي. نجاح فحص الشيفرة أو البناء لا يثبت التطابق البصري بنسبة 100% ولا أداء طابعة حقيقية؛ هذه تحتاج أجهزة ومتصفحات وبيانات مصرح بها، وتُذكر حدودها صراحة في تقرير التسليم.

في نسخة GitHub النظيفة لفرع `main` اجتاز `pnpm check` و`pnpm lint` و`pnpm check:responsive-shell` و`pnpm build` و`pnpm build:appwrite-api`. اجتاز `pnpm test -- --maxWorkers=2` جميع 414 اختباراً في 68 ملفاً. في المحاولة الافتراضية الأولى انتهى اختبار Chromium واحد بمهلة 5 ثوانٍ مع بقية المجموعة المتوازية؛ لم يكن فشل assertion، ثم اجتازت المجموعة الكاملة مع حد التوازي. أظهر بناء Appwrite تحذيرين قائمين حول `import.meta` ضمن تنسيق CommonJS، لكنه أكمل وتحقق bundle المالك وعدم تضمين Supabase SDK.

يشمل `main` endpoint Appwrite موثقاً لتحويل DOCX إلى PDF داخل مساحة الوثائق؛ لم يُنشر أو يُحدث Appwrite Function الإنتاجي هنا. يتطلب تمكين طباعة Word في Flutter نشر function المحدث بعد التحقق من إعداداته وصلاحياته على بيئة الاستضافة. لم تُختبر طابعة فعلية أو أجهزة Android/iOS؛ كما أن نجاح المتصفح/البناء لا يثبت تماثلاً بصرياً بنسبة 100% على كل جهاز.
