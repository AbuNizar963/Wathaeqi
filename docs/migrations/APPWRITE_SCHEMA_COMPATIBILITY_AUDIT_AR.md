# تدقيق مخطط Appwrite الحالي

**النطاق:** مشروع Appwrite `wathaeqi` وقاعدة `wathaeqi-db`.

## مخازن البيانات المستخدمة

| الجدول | الغرض |
| --- | --- |
| `users` | ملف حساب المالك المرتبط بمعرّف Appwrite Auth |
| `organizations` | تعريف المؤسسة المالكة للسياق |
| `organization_memberships` | ارتباط حساب المالك بالمؤسسة |
| `documents` | الوثائق الرسمية |
| `templates` | قوالب الوثائق |
| `app_records` | سجلات إعداد المالك ومفاتيح التطبيق العامة |

تستخدم المستودعات الحالية `node-appwrite` وTablesDB مباشرة، مع معاملات Appwrite في تحديثات الوثائق وحجز الرقم المتسلسل. لا يعتمد وقت التشغيل على ORM أو مخطط SQL خارجي.

## قواعد التوافق

- يبقى معرّف Appwrite `$id` هو هوية الصف في المستودعات التي تستخدمه.
- تحفظ ملكية الوثيقة والقالب في `ownerId`، وتتحقق طبقة الخادم من الملكية عند كل قراءة أو تعديل.
- لا تُنشأ ملفات تعريف مالك مكررة عند تهيئة كلمة المرور.
- لا تُنسخ تجزئات كلمات المرور القديمة إلى Appwrite Auth.
- يجب أن تبقى معاملات حجز الأرقام وتحديثات الوثائق ذرية، وأن تفشل مغلقة عند تعذر المعاملة.

## حدود هذا التدقيق

هذا المستند يصف نطاق المالك والوثائق الحالي، ولا يدعي أن كل الميزات التشغيلية التاريخية (مثل مسارات البرقيات والإشعارات متعددة المؤسسات) قد أعيد تنفيذها. أي ميزة غير موجودة في واجهة الإصدار الحالي لا ينبغي إظهارها على أنها مدعومة.
