# خطة مطابقة منصة برقيات الشرطة داخل Wathaeqi مع Appwrite

## النطاق

الهدف هو أن يطابق فرع الويب في Wathaeqi واجهة ووظائف مستودع `AbuNizar963/police-telegrams-platform` مطابقة كاملة، مع إبقاء Wathaeqi هو المستودع الوحيد الذي تُنفذ عليه التعديلات. ستبقى طبقة التطبيق والواجهات والاختبارات والميزات الأصلية كما هي، بينما تُستبدل طبقة التخزين والمصادقة والنشر القديمة بمكافئات Appwrite من دون إعادة Supabase إلى التنفيذ.

سيُطبق التغيير على فرعي Wathaeqi بصورة مستقلة: `migration/exact-police-parity-appwrite` للويب والخادم، وفرع `flutter-mobile-app` لتطبيق Flutter. لا يُدمج أي فرع في `main` ولا يُنشر إلى الإنتاج قبل اكتمال الفحوص والموافقة الصريحة.

## حدود المصدر

مستودع الشرطة مرجع قراءة فقط. لن تُنفذ عليه عمليات checkout أو commit أو push أو تغيير إعدادات أو إنشاء Pull Request. تم تثبيت حالته قبل البدء، وستُعاد قراءة `git status` للتحقق من عدم تغيّره بعد كل مجموعة عمل.

## استراتيجية النقل

أُعيدت ملفات العميل الأصلي إلى فرع Wathaeqi الجديد مع استثناء عميل Supabase القديم وملف tRPC القديم. سيُحتفظ بنفس المسارات والصفحات والتسميات والتخطيط، ثم تُضاف طبقة توافق Appwrite في الخادم بحيث تستخدم الواجهة عقود الإجراءات الأصلية نفسها. كل إجراء توافق سيحوّل الطلب إلى مستودعات Appwrite، مع التحقق الخادمي من الهوية ونطاق الجهة والدور قبل القراءة أو التعديل أو الحذف أو التصدير أو التخزين.

لن تُنقل ملفات `supabase/` أو `drizzle/` أو `server/_core/supabase.ts` أو `client/src/lib/supabase.ts` إلى التنفيذ. ستُستخدم فقط كمرجع لفهم السلوك والعقود، ثم تُنفذ الوظيفة في TablesDB وStorage وAuth وFunctions.

## بوابات التحقق

بعد كل مجموعة تعديلات سيُشغّل التنسيق، وفحص الأنواع، والاختبارات المركزة، ومجموعة الاختبارات الكاملة، وبناء الويب، واختبار توافق عقد الهاتف. سيُشغّل على فرع الهاتف `dart format`, و`flutter analyze`, و`flutter test`, وبناء Android المتاح في البيئة. كما ستُراجع GitHub Actions على الالتزام النهائي لكل فرع.

يُمنع اعتبار فحص معلّق أو ملغى أو متخطى نجاحاً. وسيُسجل في تقرير التسليم ما تم تشغيله فعلياً وما بقي غير منفذ.

## الحالة الابتدائية

أنشئ الفرع الجديد من `origin/main` في Wathaeqi فقط. أُعيدت واجهة العميل المصدرية إليه، وأظهر أول فحص للأنواع فجوات توافق متوقعة بين أسماء إجراءات المصدر وعقود Appwrite الحالية؛ لم يتم تجاوزها أو إسكاتها، وستُعالج بإجراءات توافق حقيقية واختبارات نجاح وفشل.
