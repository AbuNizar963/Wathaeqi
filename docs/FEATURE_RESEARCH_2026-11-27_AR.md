# بحث ميزات أنظمة إدارة الوثائق — 2026-11-27

## لماذا هذه المصادر

الهدف هو تحسين WATHAEQI كنظام إنشاء وثائق رسمية وأرشفة وطباعة، وليس تحويله إلى نظام مراسلات أو تبادل بين الجهات.

## نتائج قابلة للتطبيق

### Mayan EDMS

توثيق Mayan يصف نظام EDMS مؤسسيًا يعتمد على صلاحيات دقيقة، إصدارات الوثائق، سير العمل، سياسات الاحتفاظ، تتبع الأحداث، البيانات الوصفية والفهرسة. في WATHAEQI نأخذ ما ينسجم مع النطاق الحالي: تتبع الأحداث، البيانات الوصفية، وإظهار حالة الوثيقة وإصداراتها مستقبلًا. لا نضيف سير مراسلات أو توجيهًا بين جهات لأن ذلك خارج النطاق.

المصدر: https://docs.mayan-edms.com/ — "Mayan EDMS 4.12.2 documentation"

### Paperless-ngx

توثيق Paperless-ngx يوضح قيمة تنظيم الوثائق بالوسوم والجهات والأنواع، OCR والبحث الكامل، الإصدارات المتعددة، التصفية والفرز، العروض المحفوظة، التعديل الجماعي، الروابط العامة المنتهية، الصلاحيات متعددة المستخدمين، وسلامة الأرشيف. في WATHAEQI الموجود بالفعل: البحث والتصنيف والفرز والعروض المحفوظة وإدارة الصلاحيات. الأولوية الآمنة التالية هي تحسين وضوح البحث والفلاتر والبطاقات، مع تجنب إضافة روابط عامة أو OCR ما لم تتوفر متطلبات تخزين/خصوصية واضحة.

المصدر: https://docs.paperless-ngx.com/ — "Paperless-ngx"

### Microsoft SharePoint

توثيق Microsoft Learn يبرز Version History كقدرة لمشاهدة الإصدارات السابقة واستعادتها. في WATHAEQI نطابق النمط على مستوى تجربة الاستخدام: إبراز revision والتاريخ في المعاينة وسجل الحركات، وعدم تغيير بيانات الوثيقة مباشرة دون مسار واضح.

المصدر: https://learn.microsoft.com/en-us/sharepoint/version-overview — "Version History"

### مرجع التصميم المقدم

المراجع المقدمة في الطلب تشير إلى لوحات عمل وإدارة وثائق ذات قائمة جانبية واضحة، بطاقات عملية، ومساحات منظمة. نستخدمها للإلهام فقط مع الحفاظ على الهوية العربية الرسمية وعدم نسخ تصميم بعينه.

## قرارات التنفيذ

1. الإبقاء على الهوية المحددة في الطلب: كحلي `#0B1120`، بطاقات `#131C31`، سماوي/زمردي/ذهبي، وIBM Plex Sans Arabic مع Amiri للطباعة.
2. عدم إنشاء مسارات إرسال واستقبال أو شجرة جهات.
3. إضافة ميزات واجهة ذات مخاطر منخفضة: حالة اتصال مفهومة، بحث سريع، فلاتر وعروض محفوظة، إحصاءات، حالات تحميل/خطأ/فراغ، وتجربة بطاقات متجاوبة.
4. عدم تخزين حقل غير موجود في Appwrite. عند اختلاف المخطط، يجب استخدام قائمة حقول معتمدة وتخزين إعدادات التنسيق الإضافية في حقل JSON مصرح به فقط، مع اختبار قراءة/كتابة وإعادة التحميل.
5. لا تُجرى كتابات تجريبية على بيانات الإنتاج؛ فحص المخطط يكون قراءة فقط، ثم تُطبق تغييرات مخطط مضافة فقط بعد مراجعة.
