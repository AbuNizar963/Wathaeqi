# سجل حالة التسليم — فرع Appwrite

**الفرع:** `migration/appwrite-functions-transfer`  
**النطاق:** مساحة عمل المالك والوثائق في النسخة الحالية.

## المنفذ في الشيفرة

- تسجيل دخول المالك والجلسات عبر Appwrite Auth.
- تخزين ملف المالك وسياق المؤسسة وإعدادات الوثائق في Appwrite TablesDB.
- إنشاء الوثائق والقوالب وعرضها وتعديلها وإصدارها وأرشفتها عبر مستودعات Appwrite.
- حجز الرقم المتسلسل للوثيقة باستخدام معاملات TablesDB.
- تشغيل API من خلال Appwrite Function `wathaeqi-api`.
- تخزين الملفات عبر محول Appwrite Storage، مع روابط مؤقتة ورفع مرتبط بهوية Appwrite.
- حذف اعتماد ORM القديم وملفات مخطط SQL القديمة من شجرة المستودع.
- فحص CI يمنع عودة اعتماد SDK القديم إلى الشيفرة النشطة.

## ما لم يُنفذ ضمن هذا الفرع

- لم تُنقل بيانات تاريخية من أي قاعدة خارجية.
- لم تُحذف أو تُعدّل بيانات المشاريع الخارجية.
- لا يعني وجود مستودعات أو جداول تاريخية أن كل وظائف المراسلات القديمة أو إدارة المؤسسات متعددة المستخدمين متاحة في واجهة المالك الحالية.
- لم يتم الدمج إلى `main` ولم يتم نشر إنتاجي.

## المطلوب قبل الدمج

1. نجاح GitHub Actions كاملة على آخر commit، بما فيها التنسيق والأنواع والاختبارات والبناء وفحوص الأمان.
2. نجاح بناء Appwrite Function وموقع المعاينة من commit نفسه.
3. اختبار تسجيل الدخول من المتصفح وتحقق حالة إعداد المالك دون استهلاك الرمز قبل الإرسال.
4. اختبار تغيير كلمة المرور وتسجيل الخروج وإبطال الجلسة.
5. اختبار إنشاء وثيقة وحفظها وتعديلها وإصدارها وأرشفتها.
6. اختبار صلاحيات الملكية وعدم إمكانية قراءة وثيقة مالك آخر.
7. اختبار مسارات Storage إن كانت مستخدمة في الواجهة الحالية.

## المخاطر والقيود

- الحارس الإضافي لمحاولات الدخول يعتمد ذاكرة العملية ولا يشارك عداده بين نسخ متعددة؛ يجب مراجعته قبل التوسع الأفقي.
- تحذير حجم حزم الواجهة لا يعني فشل البناء، لكنه يستحق تحسيناً منفصلاً.
- نجاح Actions أو نشر المعاينة لا يثبت وحده نجاح كل سيناريو استخدام فعلي.
